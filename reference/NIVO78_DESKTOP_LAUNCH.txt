NIVO78 DESKTOP LAUNCH — Fixed .exe paths and shortcuts that do not break

Rule ID: APP-DESKTOP-FIXED-BUILD-INSTALL-PATHS [GATE]
Enforcement: every stamped Windows desktop product; verifier DesktopLaunchShortcutGuardrailTest (N78-Ops spine) + align-n78-desktop-launch.ps1 family sweep.

Scope
-----
Windows desktop utilities (WinForms and KMP Compose desktop). Android-only apps (N78-Dash, N78-Probe) are excluded.

Family mandatory contract (all desktop apps)
--------------------------------------------
Every Nivo78 Windows desktop app MUST keep build, install, and operator shortcut targets on **fixed paths that never move** when TFM, RID, Gradle output layout, or CI folder names change. Shortcuts MUST NOT point at repo clones, moving bin\Release\net*-windows\ trees, or Gradle :desktop:run scratch output.

Operator path (what the Desktop .lnk runs):
  %ProgramFiles%\{InstallFolderName}\{ExeFileName}
  Refreshed only by ensure-{product}-launch.ps1 → createDistributable/dotnet build → sync-{product}-install.ps1.

Engineering path (repo dev only — never the operator .lnk target):
  tools\launchers\{Prefix}.bat, Desktop\Apps\… twins, and optional :desktop:run / br — these build into the **same fixed repo distributable folder** defined in N78DesktopLaunchProfile.ps1, then sync to Program Files before the operator shortcut is considered current.

If Program Files is older than the fixed repo build output, the product is **not** up to date for shortcut launch until sync-{product}-install.ps1 succeeds.

Fixed locations (mandatory)
---------------------------
Desktop shortcuts and operator habits assume paths never move when TFM, RID, or Gradle folders change.

1. Repo build output — stable relative folder only
   • .NET (WinForms): vbproj/csproj MUST use a fixed OutputPath (typical bin\run\).
     Set AppendTargetFrameworkToOutputPath=false and AppendRuntimeIdentifierToOutputPath=false.
     Profile DotNetOutputRelative MUST match that folder (e.g. bin\run).
   • KMP Compose desktop: Profile GradlePackageFolder + distributable path under desktop\build\compose\binaries\main\app\{folder}.
     Do not point shortcuts at one-off bin\Release\net*-windows\... trees.

2. Program Files install — one folder per product
   • Destination: %ProgramFiles%\{InstallFolderName}\{ExeFileName}
   • sync-{product}-install.ps1 copies from the fixed repo build folder above (UAC when needed).

3. Desktop .lnk — fixed .exe only (mandatory)
   • Operator shortcut: C:\Users\{user}\Desktop\{DisplayName}.lnk ->
     C:\Program Files\{InstallFolderName}\{ExeFileName} (direct binary; no .bat/.ps1 wrapper targets).
   • N78-Ops: C:\Program Files\N78Ops\N78-Ops.exe. Refresh the binary with sync-ops-install.ps1 or
     N78-Ops-Launch.bat / ensure-ops-launch.ps1 (repo + Apps twins only — not the Desktop .lnk).
   • Do NOT point the operator desktop .lnk at Gradle output under the repo clone (path churn).
   • Do NOT point .lnk at a path inside the git clone (repo moves, branches, and CI output differ).
   • Repo tools\launchers\{Prefix}.bat and Desktop\Apps\{Product}\ twins still call ensure-*-launch.ps1.

Behavior on open
----------------
1. Operator double-clicks desktop shortcut, Apps twin, or repo launcher.
2. ensure-{product}-launch.ps1 compares source timestamps to the last build.
3. Gradle :desktop:createDistributable or dotnet build -c Release runs when stale.
4. When build output is newer than Program Files, sync-{product}-install.ps1 copies to the fixed install folder (UAC when needed).
5. App starts from Program Files when install succeeded; otherwise from the fixed repo build folder (fallback only).
6. sync-{product}-install.ps1 does not recreate shortcuts unless -RefreshShortcuts. create-desktop-shortcuts.ps1 repairs the single canonical .lnk (user Desktop preferred; removes duplicate Public Desktop copy).
